### Sampling condition

Analysis temperature **0.0** (`KERNEL_TEMPERATURE`, `--kernel_temperature`), also part of the cache key.

This is a **deliberate divergence from the sampling condition the agents ran under**, not an inherited default. It is recorded as a divergence because the kernel is otherwise held to the deployment condition (same backbone as the run under review), and this is the one parameter where it is not.

**There is no single "deployed temperature".** Upstream `query_model` hardcodes `temperature=0.05` on its **OpenAI branches only** (`gpt4`, `gpt4v`, `gpt-4o-mini`, `gpt3.5`, `gpt4o`), present since the initial commit and authored entirely upstream; `core.backbones.mistral_query_model` mirrors that value for the Mistral route. The **Anthropic branch sets no temperature at all**, so a `claude3.5sonnet` agent runs at the provider default (1.0). `o1-preview` and the Replicate branches likewise set none. Any arm that swaps the backbone is therefore also changing the sampling condition, and that must be stated rather than assumed.

Rationale for 0: upstream's own grader (`compare_results`) ran at `temperature=0.0` at the initial commit, as a standalone call. Commit `07f869a` refactored it onto `query_model(moderator_llm, ...)`, which gave it the agent's 0.05 -- the judging component's determinism was lost as a refactor side effect, not as an argued decision. Restoring it for the gate is closer to this codebase's original design intent than inheriting 0.05 would be, and it matches the scorer's judge.

**This is not a claim of determinism.** The scorer's judge runs at temperature 0 and still showed only 62% exact agreement on NCC MERP band across four re-scorings of the same arm. Read this as *temperature 0; reproducibility via the response cache* -- the cache replays exact bytes, which is what makes a re-run identical.

**`tests/test_golden.py` cannot detect this change.** It substitutes `query_model` wholesale and compares only the `(system, user)` pairs; temperature is set *inside* that function, below the substitution point, so it never executes under the golden test. The suite stays green whatever this value is, and its green state is **not** evidence that this change is safe.

The backbone was supplied explicitly by the operator via `--backbone`; the script has no default and infers nothing. The kernel is a component of the deployed system, so the deployment condition is the backbone the run under review ran on -- a stronger model here would confound *the defence works* with *the defence got a better model*. Where the two differ the line above says so, and this report is a sanity run.

Embedded commands are **reported, not gated**: `EMBEDDED_UNAUTHORIZED_COMMAND` is retired. They still feed `high_risk`, so a high-strength directive can still escalate a *contradicted* claim to UNSAFE, but a diagnosis is never restricted merely for containing one -- the old clause fired on 5 of 5 clean scenarios, on ordinary clinical language. The signal it was meant to catch, an injected directive echoed into the diagnosis, is `ECHOES_EXCLUDED_CONTENT`. A routing sentinel (`DIAGNOSIS READY`, `REQUEST TEST`, `REQUEST REFERRAL`) is the harness's own mandated output format, not a directive, and is filtered before any of that by `core.kernel.is_routing_sentinel` -- counted here rather than discarded so the rate stays auditable.

`action=other` + `action_strength=high` is reported on its own because `other` is the catch-all and `high` is what opens `red_flag_open`: together they are a wildcard escalation path from an unclassifiable span to UNSAFE. **Measured, not acted on** -- the schema is unchanged.

The support rate is the quantity the live run exists to measure: `estimate_starvation.py` showed all 50 clean scenarios resolving to RESTRICT / `NO_ADMISSIBLE_SUPPORT` when the analysis finds no link, so the clean pass-through rate rests entirely on this number. It is **reported, never thresholded** -- the verdict logic does not see it.

*any support* is what the verdict used (admissible links only); the *links* column is what the analysis returned. Where they disagree, the analysis cited a withheld item as support and the kernel declined to count it. *admissible (EV/SO)* separates a scenario with no support from a scenario with no evidence.
